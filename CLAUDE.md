# Startup Simulator

Одиночный симулятор технологического стартапа. Веб-технологии (TypeScript, React, Vite), сначала браузер, потом Steam.

## Команда

Два человека без опыта программирования, оба на macOS. Код пишется и проверяется через Claude Code. Общение — на русском, простым языком, без жаргона.

## Правила

1. Не добавлять функции, которых нет в плане, без согласования с командой.
2. Одна сессия — одна задача из плана.
3. Ядро (`src/core`) не обращается к интернету, AI, системному времени и `Math.random`. Случайность — только из генератора с seed.
4. Числа игры считает только код. AI пишет тексты и разбирает идеи в заданных пределах.
5. Любое изменение формул сопровождается тестом. Задача готова, когда тесты проходят.
6. Тексты интерфейса не пишутся в коде — только через файлы локализации.
7. Изменение структуры состояния требует функции переноса старых сохранений.
8. Не переписывать работающие части без необходимости.
9. Если документы и код расходятся — сказать об этом и обновить документ.

## Состояние на 19 ноября 2026 (обновлять при каждой крупной перемене)

**Куда игра идёт.** Про рост «от комнаты до этажа в бизнес-центре», а не про выживание впроголодь. Прежняя цель баланса («новичок разоряется на 6–10 месяце») отменена после живых партий: игра получалась скучной. Подробности и числа — `docs/02-economy.md`, разделы 15–22.

**Как выглядит.** Заставка → экран создания компании (идея своими словами, тема, нейросеть подсказывает) → пиксельная квартира основателя (`src/ui/apartment`, работа напарника; 3D-комната удалена). Всё управление компанией — в компьютере в квартире: программа «Компания» (`src/ui/office/CompanyApp.tsx`) с разделами сводка, продукт, команда, маркетинг, финансы, банк, сообщения, почта, цели, настройки. Квартира связана с расчётом через `RoomLink` (`src/ui/apartment/link.ts`).

**Что уже есть в расчёте** (`src/core`): рост и доход с ускорением (`pace`), силы основателя, кофе и отдых, набор кода игроком ускоряет работу, 35 событий (в том числе о сотрудниках и шесть развилок в разработке), лестница из 25 целей, сотрудники с чертой характера и движущей силой, разговор один на один, офисы на 3–80 мест, три раунда инвестиций, банк (кредит и вклад), 11 тем со своими функциями и рынком, 7 типов продукта (включая «Игру»), лента новостей с отзывами, причина банкротства.

**Нейросеть.** Посредник — `tools/ai-server` (общий код `core.ts`; `plugin.ts` для `npm run dev`, `server.ts` для сервера). Три запроса: разбор идеи, три идеи по теме, разговор с сотрудником. Ключ лежит в `.env.local` (`AI_API_KEY=`) и на сервере; в репозиторий, в сборку и в чат он не попадает. Модель — `claude-haiku-5-5`. Нейросеть никогда не задаёт числа: она выбирает из заданных вариантов, а расчёт проверяет ответ.

На стыке:
- Новая механика: правило в ядре и команда или данные для экрана. Если нужно что-то показать — простой рабочий экран и пометка в запросе на слияние «нужно оформление». Оформляет напарник.
- Квартира получает данные игры только через `RoomLink` (`src/ui/apartment/link.ts`). Новое поле добавляется в `RoomLink` и `src/ui/office/GameRoom.tsx`; как оно выглядит в сцене, решает напарник.
- Нейросеть: адреса, запросы и проверка ответов — на стороне владельца. Нужен новый адрес — напарник просит, владелец делает.
- Тексты для своих механик можно добавлять в `src/content/ru/*.json`; формулировки потом правит напарник.
- В чужие файлы не лезть. Если очень надо — сначала договориться.

**Порядок работы с git.**
- В `main` напрямую не отправлять. Каждая задача — в своей ветке → запрос на слияние → второй смотрит и сливает в течение дня. Это отменяет прежнее разрешение сессии самой отправлять в `main`.
- Перед началом задачи подтянуть свежий `main` в свою ветку.
- Запросы маленькие: одна задача — один запрос, со снимками экрана, если что-то видно глазами.
- Инструмента `gh` на компьютере владельца нет: сессия отправляет ветку и даёт ссылку вида `https://github.com/Programisst/Startup_Simulator/pull/new/<ветка>`, запрос открывает и сливает человек.
- Проверка на GitHub идёт в несколько раз медленнее, чем локально: долгие тесты должны иметь запас по времени (см. `tests/balance.test.ts`).
- Обновить игру на сервере — `npm run deploy`, только по просьбе владельца.

**Проверка баланса.** `npm run balance -- 60 all`. Цели записаны тестами в `tests/balance.test.ts`: на обычной сложности грамотный игрок почти всегда выживает, новичок — чаще да, чем нет; сложная проходима только хорошей игрой; «ничего не делать», «только подработка» и «нанять сильного в первый день» ведут к банкротству. Баланс чувствителен: лишние $300–500 в начале партии меняют исход, поэтому после любой правки чисел прогонять ботов.

**Сохранения.** Версия формата — 1. Все поля, добавленные после первой версии, необязательные, и ядро само подставляет значения по умолчанию. Так делать и дальше: старые партии должны открываться.

**Чего ещё нет.** Сотрудников не видно в квартире, и переезд в офис не меняет картинку. Английский перевод есть только у событий. Аккаунтов игроков и оплаты нет: ссылка на сервер открытая, расход ограничен суточными пределами. Налоги, юрлицо и рекламные каналы из первоначальных пожеланий не начаты.

**Как проверять, не видя экран.** Владелец играет на `http://localhost:5173` и присылает снимки. Тесты и снимки из браузера без экрана не заменяют его ощущений: после заметных изменений просить сыграть партию. Заставка и квартира напарника в браузере без экрана не рисуются — их может оценить только человек.
