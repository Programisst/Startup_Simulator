# План разработки, роли и риски

Версия 0.1.

Сроки даны в часах работы команды, а не в датах, потому что время на проект у вас плавает. Оценки грубые: умножайте на полтора, если этап первый в своём роде.

## 1. Этапы

| № | Этап | Результат | Часы команды |
|---|---|---|---|
| 0 | Подготовка | Оба компьютера настроены, проект лежит на GitHub, пустая страница открывается | 3–5 |
| 1 | Ядро без экранов | Симуляция считает партию, тесты проходят, есть прогон баланса | 15–20 |
| 2 | Играбельный прототип | MVP из GDD: в игру можно играть в браузере | 25–40 |
| 2.5 | Реализм | Юридическое лицо, налоги, рекламные каналы, ещё 20–25 событий | 15–25 |
| 3 | AI | AI-разъём, разбор свободной идеи, живые тексты через ключ разработчика | 15–25 |
| 4 | Сотрудники и драма | Наём, характеры, мотивация, события вокруг людей | 30–50 |
| 5 | Инвесторы и конкуренты | Раунды инвестиций, компании-соперники | 30–50 |
| 6 | Публичная демо-версия | Игра на itch.io, английский язык, сбор отзывов, правка баланса | 20–40 |
| 7 | Версия для компьютера | Приложение для Windows и macOS, локальная модель по кнопке, страница в Steam | 40–60 |
| 8 | После выхода | 2D-офис, облачный AI с подпиской, мультиплеер | не оценивается |

До прототипа, в который можно играть: 43–65 часов.
До публичной демо-версии: 140–230 часов.

После этапа 2 обязательная остановка: играете сами и даёте поиграть 3–5 знакомым. Если не интересно — чиним ядро игры, а не добавляем новое.

## 2. Этап 0 — подготовка

Задачи:
1. Установить на оба компьютера Node.js, Git, VS Code, Claude Code.
2. Завести аккаунты на GitHub, создать закрытый репозиторий, дать доступ обоим.
3. Создать каркас проекта и структуру папок.
4. Настроить автоматический запуск тестов при каждой отправке кода на GitHub.

Готово, когда: каждый из вас на своём компьютере одной командой запускает игру и видит пустую страницу с названием, и одной командой запускает тесты.

## 3. Этап 1 — ядро без экранов

Задачи:
1. Состояние компании и генератор случайности с seed.
2. Шаг дня: пользователи, отток, конверсия, доходы, расходы.
3. Разработка продукта: функции, ошибки, технический долг, качество.
4. Репутация, кассовый разрыв, банкротство, оценка компании.
5. Команды игрока.
6. Механизм событий с выбором и 5 событий для проверки.
7. Параметры шести типов продукта.
8. Тесты формул, тест повторяемости.
9. Прогон баланса: 1000 партий с простыми стратегиями, таблица результатов.

Готово, когда:
- все тесты проходят;
- одинаковый seed даёт одинаковую партию;
- прогон показывает: стратегия «ничего не делать» разоряется, стратегия «только реклама при плохом продукте» разоряется, разумная стратегия выживает в 30–60% партий;
- шесть типов продукта дают заметно разные графики роста.

## 4. Этап 2 — играбельный прототип

Задачи:
1. Экран создания стартапа.
2. Верхняя панель: дата, деньги, пауза и скорости.
3. Экран «Обзор» с графиком и лентой событий.
4. Экран «Продукт».
5. Экран «Маркетинг».
6. Экран «Финансы».
7. Карточка события с выбором.
8. Сохранение, загрузка, автосохранение.
9. Экран итогов партии.
10. Ещё 20–25 событий.
11. Объяснение любого показателя по нажатию.

Готово, когда:
- партию можно пройти от создания компании до победы или банкротства без ошибок;
- сохранение и загрузка возвращают ту же партию;
- посторонний человек играет 30 минут без подсказок;
- хотя бы трое из пяти тестеров сами начинают вторую партию.

## 5. Распределение ролей

Оба работаете через Claude Code, поэтому делить нужно не по умениям, а по зонам ответственности, чтобы не править одни и те же файлы.

| | Участник А — «Симуляция» | Участник Б — «Игра и тексты» |
|---|---|---|
| Папки | `src/core`, `tools/balance`, `tests` | `src/ui`, `src/content`, `src/save` |
| Отвечает за | Формулы, баланс, прогоны, числа | Экраны, удобство, события, тексты, переводы |
| Главный вопрос | «Модель ведёт себя правдоподобно?» | «В это интересно и понятно играть?» |

Кто из вас А, а кто Б — решите сами. Подсказка: А ближе тому, кто любит таблицы и цифры, Б — тому, кто любит придумывать ситуации и замечает неудобства.

**Общая граница.** Описание состояния игры и список команд — общий файл. Его меняете только по договорённости, потому что от него зависят обе зоны.

**Правила совместной работы:**
1. Каждая задача делается в отдельной ветке и попадает в основную только после прохождения тестов.
2. Основная ветка всегда запускается.
3. Одна сессия с Claude Code — одна задача из плана. Не «сделай игру лучше», а «добавь экран маркетинга».
4. Перед началом работы забираете свежую версию с GitHub.
5. Раз в неделю созвон на 30 минут: что сделано, что мешает, что дальше.
6. Спорные решения по игре — вдвоём. Если не договорились, пробуете более простой вариант первым.

Всю работу с Git Claude Code делает сам по вашей просьбе; команды учить не нужно, нужно понимать смысл: ветка, сохранение изменений, отправка.

## 6. Риски

| Риск | Насколько вероятен | Что делаем |
|---|---|---|
| Проект брошен до играбельной версии | Высокий | Короткий путь до этапа 2, никаких новых идей до его конца |
| Разрастание задумки | Высокий | Всё новое записывается в список «потом», а не делается сразу |
| Код, который никто из вас не понимает, начинает ломаться | Высокий | Тесты на всё ядро, маленькие изменения, жёсткие границы между частями |
| Игра считает правильно, но играть скучно | Средний | Остановка после этапа 2, живые тестеры, события с выбором уже в MVP |
| Баланс: одна стратегия всегда выигрывает | Средний | Прогоны тысяч автоматических партий после каждого изменения формул |
| Расходы на AI превышают доход | Средний | Игра работает без AI, предел запросов, замер стоимости партии до решений о подписке |
| Подписку не покупают | Средний | Не строить на ней план заработка; основа — разовая покупка игры |
| Локальная модель пишет плохо или не идёт на слабых компьютерах | Средний | Проверка на этапе 7, запасные готовые тексты всегда на месте |
| Не на чем проверить Windows-версию | Средний | Браузерная версия снимает вопрос до этапа 7; дальше — автоматическая сборка на GitHub и знакомые с Windows |
| Конфликты при одновременной правке | Низкий при соблюдении зон | Разделение папок, отдельные ветки |
| Потеря работы | Низкий | Всё на GitHub с первого дня |
| Чужие картинки, шрифты, звуки с неподходящей лицензией | Низкий | Только материалы с лицензиями, разрешающими продажу; список источников в отдельном файле |

## 7. Чего не делаем до публичной демо-версии

Мультиплеер, подписка, аккаунты, 2D-офис, 3D, мобильная версия, звук и музыка, собеседования-диалоги, достижения.
