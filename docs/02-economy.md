# Экономическая модель

Версия 0.1. Все числа — стартовые значения. Они будут настраиваться прогонами тысяч автоматических партий (см. [план](04-roadmap.md), этап 1).

Модель считается один раз за игровой день. Месячные ставки переводятся в дневные так:
`дневная = 1 − (1 − месячная)^(1/30)`.

## 1. Состояние компании

| Обозначение | Что это | Диапазон |
|---|---|---|
| `cash` | Деньги на счёте | любое |
| `U` | Активные пользователи (всего) | ≥ 0 |
| `P` | Из них платящие | 0…U |
| `Q` | Качество продукта | 0…100 |
| `R` | Репутация | 0…100 |
| `debt` | Технический долг | 0…100 |
| `bugs` | Известные ошибки | ≥ 0 |
| `capacity` | Сколько пользователей выдерживают серверы | ≥ 0 |
| `price` | Цена в месяц или за покупку | ≥ 0 |
| `adSpend` | Рекламный бюджет в день | ≥ 0 |

Параметры рынка задаются типом продукта и аудиторией:

| Обозначение | Что это |
|---|---|
| `M` | Размер рынка — сколько людей вообще могут стать пользователями |
| `fit` | Насколько идея подходит аудитории, 0.5…1.5 |
| `K` | Давление конкурентов, 0…1 |

## 2. Привлечение пользователей

Новые пользователи за день складываются из трёх источников.

**Платная реклама**
```
CAC = CAC_base × (1 + K) / fit × (1 + 3 × (U / M)²)
paid = adSpend / CAC
```
Чем сильнее конкуренты и чем больше рынка уже занято, тем дороже пользователь.

**Органический рост**
```
organic = (M − U) × organic_base × (R / 100) × fit
```
Зависит от репутации: о плохом продукте не пишут и не ищут.

**Рекомендации (вирусность)**
```
viral = U × viral_base × (Q / 100)² × (1 − U / M)
```
Качество стоит в квадрате: посредственный продукт почти не рекомендуют, отличный растёт сам.

**Итог**
```
newUsers = (paid + organic + viral) × шум
```
`шум` — случайный множитель от 0.9 до 1.1.

## 3. Отток

```
churn = churn_base × (2 − 1.5 × Q / 100) × (1 + overload) × (1 + bugs_penalty)
```
- При `Q = 100` отток вдвое ниже базового, при `Q = 0` — вдвое выше.
- `overload = max(0, U / capacity − 1)` — перегрузка серверов.
- `bugs_penalty = min(1, bugs / 20)`.

Для платящих дополнительно учитывается цена:
```
churn_paying = churn × 0.6 × max(1, price / price_ref)
```
Платящие уходят реже, но завышенная цена это съедает.

Так реализуется главный закон из задания: плохой продукт с большим рекламным бюджетом набирает людей и тут же их теряет.

## 4. Конверсия в платящих

Доля бесплатных пользователей, которые за месяц начинают платить:
```
conv = conv_base × (Q / 100) × exp(1 − price / price_ref)
```
Ограничена сверху значением `3 × conv_base`. При цене выше ориентира конверсия быстро падает, при цене ниже — растёт, но доход с каждого меньше.

## 5. Доходы за день

| Бизнес-модель | Формула |
|---|---|
| Подписка | `P × price / 30` |
| Реклама | `U × ad_revenue_per_user / 30 × (R / 100)` |
| Разовая покупка | `newUsers × conv × price` |
| Комиссия | `U × commission_per_user / 30 × (R / 100)` |

С платежей удерживается 3% комиссии платёжной системы.

## 6. Расходы за день

```
серверы      = capacity × server_cost_per_user / 30
реклама      = adSpend
инструменты  = фиксированная сумма / 30
зарплаты     = сумма зарплат / 30      (с шага 2)
офис         = аренда / 30             (позже)
```

Серверная мощность покупается ступенями. Игрок платит за мощность, а не за фактических пользователей — лишняя мощность стоит денег, недостаточная вызывает отток.

## 7. Разработка продукта

**Скорость работы**
```
workPerDay = Σ по сотрудникам (навык × мотивация × доля времени на продукт)
```
В MVP работает один основатель с навыком 1.0.

**Функции.** У каждой есть стоимость в единицах работы и ценность `value`.
```
featureScore   = Σ value готовых функций
expectation(t) = expectation_0 × (1 + 0.015)^(месяцы с начала игры)
Q_raw = 100 × (1 − exp(−featureScore / expectation(t)))
Q     = Q_raw × (1 − 0.5 × debt / 100) − min(30, bugs × 1.5)
```
Ожидания рынка растут на 1.5% в месяц, поэтому качество без новых функций постепенно снижается.

**Спешка.** Работа идёт в 1.4 раза быстрее, но каждая готовая функция добавляет технический долг и больше ошибок.

**Ошибки.** Каждая выпущенная функция добавляет случайное число ошибок. Исправление — отдельная задача, конкурирующая за время с новыми функциями.

## 8. Репутация

Меняется медленно и тянется к целевому значению:
```
R_target = Q − штраф за перегрузку − штраф за недавние скандалы
R = R + (R_target − R) × 0.01      за день
```
Потерять репутацию можно быстро через события, вернуть — только временем.

## 9. Кассовый разрыв и банкротство

- `cash < 0` — начинается отсчёт 30 дней и приходят события о спасении: срочный заём под высокий процент, продажа доли, отказ от серверов.
- 30 дней подряд с `cash < 0` — банкротство, конец партии.
- Если `cash` вернулся выше нуля, отсчёт сбрасывается.

## 10. Оценка компании

```
ARR = месячный доход × 12
multiple = 3 + 12 × clamp(рост дохода за 3 месяца, 0, 1)
valuation = ARR × multiple + U × user_value
```
Быстрорастущая компания стоит дороже при том же доходе.

## 11. Стартовые параметры по типам продукта

Месячные значения.

| Тип | Рынок `M` | `CAC_base` | Отток | Конверсия | Цена-ориентир | Вирусность | Органика | Сервер на пользователя |
|---|---|---|---|---|---|---|---|---|
| SaaS для бизнеса | 200 тыс. | $80 | 4% | 4% | $30 | 0.05 | 0.17% | $0.05 |
| Социальная сеть | 20 млн | $1.5 | 12% | 1% | $5, реклама $0.60 | 0.40 | 0.01% | $0.02 |
| Мобильное приложение | 5 млн | $2.5 | 15% | 3% | $5 | 0.15 | 0.015% | $0.01 |
| AI-продукт | 2 млн | $12 | 9% | 5% | $20 | 0.25 | 0.1% | $0.30 |
| Маркетплейс | 1 млн | $8 | 8% | — | комиссия $5 | 0.20 | 0.018% | $0.03 |
| Инструмент для разработчиков | 500 тыс. | $25 | 5% | 3% | $15 | 0.30 | 0.072% | $0.05 |

«Органика» — какая доля свободного рынка за месяц находит продукт сама при репутации 100 и полном соответствии идеи.

Типы должны ощущаться по-разному: SaaS растёт медленно, но стабильно; соцсеть — быстро, но почти не зарабатывает; AI-продукт упирается в дорогие серверы.

## 12. Случайность и повторяемость

- Вся случайность берётся из одного генератора с начальным числом (seed), которое хранится в сохранении.
- Одинаковый seed и одинаковые действия игрока всегда дают одинаковую партию.
- Случайность влияет на четыре вещи: рынок партии (соответствие идеи, цена рекламы и отток отличаются от базовых на ±20%), шум притока пользователей (±10%), число ошибок в новой функции, события и их случайные исходы.
- Ни одна формула не обращается к AI.

## 13. Что изменено по итогам первых прогонов

- Комиссия маркетплейса теперь зависит от репутации. Иначе плохой продукт с рекламой оставался прибыльным.
- Рост ожиданий рынка снижен с 3% до 1.5% в месяц: при 3% качество падало даже у продукта со всеми функциями.
- Ступени серверной мощности сделаны мельче: при крупных ступенях AI-продукт разорялся на одном переходе.
- Цель «прибыль» — это 3 месяца подряд с прибылью от $3 000, а не просто выше нуля.
- Фактические числа лежат в `src/content/config.ts` и `src/content/productTypes.ts`. Если они расходятся с этим документом, верны файлы.

## 15. Баланс и давление денег (ветка core/money-pressure)

### Что было не так

1. На обычной сложности подработка давала $1 200 в месяц, а жизнь стоила $800. Деньги росли без всякого продукта: в живой партии из $3 000 к 7-му месяцу стало $11 000.
2. Заём в кризис можно было брать каждые 90 дней, и мёртвая компания жила на займах годами.
3. Исход партии определялся типом продукта, а не игроком: маркетплейс побеждал всегда, SaaS, соцсеть и AI-продукт — никогда.

### Что изменено и почему

**Подработка всегда приносит меньше, чем стоит жизнь.** Это правило для всех уровней сложности, оно закреплено тестом. Без продукта компания умирает всегда, подработка только оттягивает конец.

| Сложность | Старт | Жизнь в месяц | Подработка на полный день | Рынок | Было |
|---|---|---|---|---|---|
| Лёгкая | $5 000 | $700 | $600 | мягче на 5% | $6 000 / $500 / $1 500 / мягче на 15% |
| Обычная | $3 000 | $800 | $700 | базовый | $3 000 / $800 / $1 200 / базовый |
| Сложная | $2 500 | $850 | $740 | жёстче на 5% | $2 000 / $1 100 / $1 400 / жёстче на 20% |

Уровни стали ближе друг к другу по числам, потому что игра очень чувствительна к запасу денег: разница в $300 стартового капитала меняет шансы разумного игрока с 46% до 82%.

**Заём в кризис — не чаще раза в год** (`cashCrisis.cooldownDays`: 90 → 360). Второй кассовый разрыв за год теперь означает банкротство.

**Типы продуктов выровнены**, чтобы на обычной сложности каждый был на грани:

| Тип | Что изменено | Почему |
|---|---|---|
| SaaS | органика 0.04% → 0.17% | При прежнем значении первые платящие появлялись позже, чем кончались деньги |
| Социальная сеть | органика 0.005% → 0.01%, доход с рекламы $0.15 → $0.60 на пользователя | Пользователей набирала, но доход не покрывал даже серверы |
| Мобильное приложение | органика 0.01% → 0.015% | Небольшая поправка до грани |
| AI-продукт | серверы $0.60 → $0.30, конверсия 3.5% → 5%, органика 0.03% → 0.1% | Серверы съедали доход раньше, чем появлялись платящие. Серверы всё ещё самые дорогие среди типов |
| Маркетплейс | органика 0.02% → 0.018% | Был заметно легче остальных |
| Инструмент для разработчиков | органика 0.05% → 0.072% | Небольшая поправка до грани |

**Разброс рынка партии увеличен с ±15% до ±20%**, чтобы партии одного типа отличались друг от друга.

### Автоматические игроки

| Игрок | Как играет |
|---|---|
| `idle` | Ничего не делает |
| `sideJobOnly` | Только подработка на полный день, продукт не делает |
| `adsOnly` | Делает основу, запускается, льёт деньги в рекламу |
| `novice` | Без подработки, запускается сразу, реклама $10 в день, продукт потом развивает медленно |
| `sensible` | Делает три функции, потом запускается; подрабатывает, когда денег мало; рекламу включает, только если она окупается |
| `expert` | То же, но запускается сразу после основы |

| Лёгкая | ничего не делать | 0% | 10 |
| Лёгкая | только подработка | 0% | 40 |

| Лёгкая | разумный | 100% | — |
| Обычная | ничего не делать | 0% | 7 |
| Обычная | только подработка | 0% | 26 |

По типам продукта разумный игрок на обычной сложности выживает в 37–55% партий: SaaS 44%, соцсеть 55%, мобильное 38%, AI 53%, маркетплейс 42%, инструмент для разработчиков 37%.

Цели из GDD выполнены: новичок на обычной сложности разоряется на 6-м месяце, разумный игрок выживает в 46% партий.

### Что важно знать

- **Решения важнее удачи.** Одно решение — запуститься сразу после основы, а не после трёх функций — поднимает шансы на обычной сложности с 46% до 100%. Причина: пользователи и репутация начинают копиться на два месяца раньше.
- **Баланс стоит на узкой грани.** Автоматический игрок всегда действует одинаково, поэтому небольшое изменение числа резко меняет его результат. Органика ±12% сдвигает выживаемость типа с 25% до 67%. Любая правка чисел в `src/content` может уронить тесты баланса — это задумано: тесты напоминают перепроверить баланс.
- **Люди играют разнообразнее ботов.** Эти проценты — ориентир, а не прогноз. Окончательно сложность нужно проверять на живых игроках.
- **Опытный игрок на обычной сложности побеждает всегда.** Это соответствует цели «победа со второй-третьей попытки», но означает, что обычная сложность быстро перестанет быть вызовом для того, кто понял приём с ранним запуском. Возможное решение на будущее — штраф к репутации за выход с сырым продуктом.
- Проверка: `npm run balance -- 200 all` — сводка по трём сложностям; `npm run balance -- 200 normal` — по типам продукта.
